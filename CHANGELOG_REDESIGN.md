# КиберРадар — результат модернизации

## Что изменено

### Пользовательский интерфейс
- Полностью обновлены визуальные стили основного сайта: тёмная технологичная тема по умолчанию, более ясная типографика, единые поверхности и акценты.
- Переработана шапка и навигация, добавлено компактное мобильное меню.
- Главная страница получила новый первый экран, быстрый выбор дисциплины, показатели каталога, сортировку и удобную панель фильтров для мобильных устройств.
- Поиск дополнительно учитывает название, оператора, город, дисциплину и платформу.
- Добавлены состояния панели мобильных фильтров и закрытие по Escape.
- Панель модерации оформлена в общей визуальной системе с основным сайтом.
- Демонстрационная форма «Заявка на участие», которая показывала успешный результат без фактической отправки заявки, заменена честным блоком перехода к официальному организатору.

### Данные и SEO
- 15 ручных записей вынесены из `index.html` в `data/static-tournaments.json`.
- Основной сайт и генератор SEO-страниц используют единый файл каталога.
- `scripts/build-pages.mjs` больше не извлекает массив ручных турниров из HTML регулярными выражениями.
- Обновлена генерация SEO-страниц, каталога, sitemap и robots; после сборки создано 27 страниц турниров и каталог.
- В `site.config.json` закреплён используемый генератором ориентировочный курс USD/RUB (75). Клиентская часть использует тот же текущий fallback 75.

### ВК-модерация и PHP API
- Кандидаты ВКонтакте и статистика обхода загружаются модерацией через авторизованный `api/vk.php?action=load`, а не прямыми публичными запросами браузера к JSON-файлам.
- API выдаёт кандидатов и статистику только после проверки сессии модератора.
- Добавлены защитные HTTP-заголовки API и дополнительная проверка Origin / Fetch Metadata для POST-запросов.
- Чтение и запись связанных файлов модерации синхронизированы через `data/.vk-save.lock`: чтение использует shared lock, сохранение — exclusive lock.
- Запись JSON выполняется через временный файл и атомарное переименование; убран небезопасный fallback с копированием поверх существующего файла.
- Ревизия учитывает также опубликованный `data/vk.json`, чтобы обнаруживать изменения всего набора.
- Добавлены `.htaccess` для ограничения доступа к служебным JSON и PHP-конфигурации, а также базовые защитные заголовки.
- `data/.vk-save.lock` добавлен в `.gitignore` и исключения FTP, чтобы деплой не удалил активную блокировку. Серверный `api/config.php` исключается из FTP, если секрет `MODERATOR_PASSWORD` не задан; при наличии секрета конфиг пересоздаётся и выкладывается.

### Публикация и сопровождение
- GitHub Pages теперь получает только статический публичный артефакт: основной HTML, публичные JSON и SEO-страницы. PHP API, moderation.html, скрипты и служебные данные не копируются в Pages artifact.
- Workflow обновления учитывает новый JSON-каталог и защитные файлы.
- Добавлены npm-команды `npm test` и `npm run build:seo`.
- README обновлён с новой структурой, деплоем, API и защитой серверных файлов.

## Проверки

- `node --test scripts/test.mjs` — 15/15 тестов пройдены.
- `node --check scripts/build-pages.mjs` — пройдено.
- `php -l api/vk.php` — синтаксических ошибок нет.
- Inline JavaScript в `index.html` и `moderation.html` проверен через `node --check`.
- В HTML нет повторяющихся `id`.
- `node scripts/build-pages.mjs` — успешно, сгенерированы 27 страниц турниров, каталог, sitemap и robots.
- Локальный PHP smoke-test: ping `200`, неавторизованный load `401`, чужой Origin `403`, корректный тестовый вход `200`, авторизованный load `200`.

## Что не проверено на реальном окружении

- Реальные FACEIT и VK API не вызывались: в архиве нет ключей `FACEIT_API_KEY` и `VK_TOKEN`.
- Реальные запросы Supabase не выполнялись: в предоставленном архиве параметры `SUPABASE_URL` и `SUPABASE_ANON_KEY` пустые.
- Реальная отправка Formspree не проверялась: `FEEDBACK_ENDPOINT` не настроен.
- FTP-деплой и работа на боевом хостинге не выполнялись: отсутствуют FTP-доступы.
- Правила `.htaccess` проверены по содержимому, но не через реальный Apache на хостинге. Если сервер не Apache или запрещает `.htaccess`, нужно настроить эквивалентные правила у хостера.
- Визуальный рендер в headless Chromium не удалось надёжно получить в текущей среде; адаптивные правила и DOM/JS проверены статически, но финальный осмотр на реальных устройствах ещё нужен.

## Архитектурное решение

В этой итерации сохранена существующая статическая архитектура фронтенда и Node.js-конвейеры, а не сделана рискованная миграция на React/Vite. Причина — сохранить стабильный FTP/PHP-деплой, существующие URL и SEO-страницы без потери интеграций. PHP API усилен и расширен, но не превращён в отдельный сервер приложения.

## Важно перед публикацией

1. Сохранить резервную копию действующего сайта и серверных файлов.
2. Загрузить `index.html`, `moderation.html`, `api/vk.php`, три `.htaccess`, `data/static-tournaments.json`, остальные публичные JSON и папку `t/`.
3. Не перезаписывать на сервере `api/config.php`, `data/vk.json`, `data/vk-decisions.json`, `data/vk-skip.json`, `data/.login-fail.json` и `data/.vk-save.lock`.
4. Убедиться, что FTP-секреты и `MODERATOR_PASSWORD` настроены в GitHub Actions.
5. Проверить `/api/vk.php?action=ping`, затем вход и сохранение в `/moderation.html` уже на боевом хостинге.
