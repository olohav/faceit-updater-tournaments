# КиберРадар

Сайт-агрегатор турниров по CS2, Dota 2, Valorant и MLBB для России.
Статический сайт (`index.html`) + автосбор FACEIT (`scripts/`) + аккаунты, роли и ручные турниры (Supabase) + форма обратной связи (Formspree).

## Структура
| Путь | Назначение |
|---|---|
| `index.html` | интерфейс сайта |
| `data/static-tournaments.json` | единый источник ручных турниров для сайта и SEO |
| `data/faceit.json` | турниры FACEIT (обновляется скриптом) |
| `data/vk-candidates.json` | все найденные анонсы из ВК (пишет автосбор, на сайт не попадают) |
| `data/vk-stats.json` | статистика последнего обхода ВК (сколько постов просмотрено и почему отброшено) |
| `data/vk.json`, `data/vk-decisions.json`, `data/vk-skip.json`, `data/.vk-save.lock` | одобренные турниры, решения модератора и блокировка одновременной записи. **Живут только на хостинге**, их использует `api/vk.php` |
| `moderation.html`, `api/vk.php`, `lib/` | страница модерации на сайте, её серверная часть и общий код расчёта |
| `data/organizers.json` | кэш имён организаторов (ускоряет скрипт) |
| `scripts/config.mjs` | **все настройки отбора**: игры, поисковые слова, фильтры |
| `scripts/sync-faceit.mjs` + `api/filters/format/parse/dates.mjs` | сбор и обработка данных |
| `supabase/schema.sql` | база: аккаунты, роли, турниры администратора |
| `.github/workflows/` | автообновление и публикация |

## 1. Автоматический сбор FACEIT
GitHub: Settings → Secrets → Actions → секрет `FACEIT_API_KEY` (ключ типа Server side). Workflow «Update site data» запускается каждый час (подробнее в разделе 6).
Локально: `set FACEIT_API_KEY=ключ` и `node scripts\sync-faceit.mjs`. С `set FACEIT_DEBUG=1` скрипт дополнительно создаёт `data/filter-report.json`: сколько турниров отсеяно по каждой причине и примеры названий. Так видно, не выпадает ли нужное.

## 2. Обратная связь на почту (Formspree, бесплатно)
1. formspree.io → зарегистрироваться (почта dezhenkov62@gmail.com) → New form.
2. Скопировать адрес формы вида `https://formspree.io/f/xxxxxxx`.
3. В `index.html` вписать его в `const FEEDBACK_ENDPOINT = "…"`. Письма будут приходить на почту, на которую зарегистрирована форма. Лимит бесплатного тарифа — несколько десятков сообщений в месяц.

## 3. Аккаунты, роли и админ-панель (Supabase, бесплатно)
1. supabase.com → New project (регион поближе, придумайте пароль БД).
2. SQL Editor → New query → вставить `supabase/schema.sql` → Run.
3. Project Settings → API: скопировать **Project URL** и ключ **anon public**. В `index.html` вписать в `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Ключ `service_role` в сайт вставлять нельзя.
4. Authentication → URL Configuration: в Site URL указать адрес сайта (например `https://olohav.github.io/faceit-updater-tournaments/`).
5. Зарегистрироваться на сайте почтой администратора, подтвердить письмо, затем в SQL Editor выполнить:
   `update public.profiles set role = 'admin' where email = 'dezhenkov62@gmail.com';`
6. Выйти и войти заново: в шапке появится «Администратор» и «Админ-панель».

Безопасность: права проверяет сама база (политики RLS), а не страница. Обычный пользователь не может ни добавить турнир, ни изменить свою роль, даже если подправит код в браузере.

## Роли
- **Пользователь**: регистрация и вход, форма обратной связи с подставленной почтой.
- **Администратор**: всё то же + вкладка «Админ-панель»: добавление, редактирование, удаление турниров, дата автоудаления.

## 4. Страницы для поисковиков (SEO)
Главная страница рисуется скриптом и использует адреса вида `#/t/…`, которые поисковики не индексируют отдельно. Поэтому `scripts/build-pages.mjs` создаёт обычные HTML-страницы:
- `t/<id>/index.html` — страница каждого актуального турнира (заголовок, описание, разметка schema.org для поиска, ссылки на похожие турниры);
- `t/index.html` — каталог всех турниров;
- `sitemap.xml` и `robots.txt` — для Яндекса и Google.

Источники: `data/static-tournaments.json`, `data/faceit.json` и турниры администратора из Supabase (берутся автоматически, если подключён). Фронтенд и SEO-генератор читают один и тот же JSON; генератор больше не извлекает список турниров из исходного HTML. Для публикации ручных записей из Supabase он по-прежнему использует публичные `SUPABASE_URL` и `SUPABASE_ANON_KEY` из конфигурации основного сайта.
Адрес сайта указан в `site.config.json` (`siteUrl`). **При смене домена поправьте его там и запустите скрипт заново.**

Запуск на Windows: `update-site.bat` (обновляет данные FACEIT и создаёт страницы). Затем загрузите на хостинг в корневую папку сайта: `index.html`, `data/faceit.json`, `data/static-tournaments.json`, папку `t/`, `sitemap.xml`, `robots.txt` и защитные `.htaccess` файлы из корня, `data/` и `api/`. Не заменяйте серверные `data/vk.json`, `data/vk-decisions.json`, `data/vk-skip.json`, `data/.vk-save.lock` и `api/config.php`. Завершённые турниры при каждом запуске исчезают из `t/`, поэтому папку `t/` на хостинге лучше заменять целиком.

После публикации на своём домене: добавьте сайт в Яндекс Вебмастер (webmaster.yandex.ru) и Google Search Console, укажите адрес `…/sitemap.xml`.

## 5. ВКонтакте: от поста клуба до сайта
1. **Автосбор** (GitHub, раз в 6 часов): `scripts/vk-tournaments.mjs` читает стены клубов из `data/clubs.json`, отбрасывает итоги, новости про про-сцену и закрытую регистрацию, остальное кладёт в `data/vk-candidates.json`. На сайт эти анонсы **не попадают**. Статистика прогона в `data/vk-stats.json`.
2. **Проверка прямо на сайте**: откройте `https://ваш-домен/moderation.html`, войдите по паролю. Одинаковые посты разных клубов сети склеены в **одно событие** (89 постов CyberX = одна карточка). Одна кнопка «Одобрить» одобряет все посты события, в том числе те, что клубы опубликуют позже. «Править» меняет название, дату, время, приз, игры и организатора сразу для всех постов события. «Посты» показывает клубы, там можно исключить пост или скрыть клуб.
3. **Публикация мгновенная**: после каждого действия страница получает кандидатов и статистику через авторизованный `api/vk.php`, считает итоговый список и отправляет его на сервер. API записывает `data/vk.json` на хостинге. Кандидаты и служебная статистика не выдаются прямыми публичными URL при работе на Apache-хостинге. Обновите главную, и турнир уже там. GitHub не участвует.
4. Турнир уходит с сайта сам, когда наступает время старта.

Без даты одобрить событие нельзя: сначала укажите её через «Править».

## 6. Автоматизация на GitHub
Один workflow `Update site data` (`.github/workflows/update-data.yml`):

| Когда | Что делает |
|---|---|
| каждый час | автотесты, FACEIT, страницы для поисковиков, коммит, FTP |
| каждые 6 часов | то же + обход ВК-групп клубов (около 30 минут) |
| вы изменили `index.html`, `moderation.html`, `api/`, `lib/` | загрузка на хостинг без запросов к FACEIT и ВК |
| кнопка Run workflow | всё сразу |

Источники не зависят друг от друга: если упал FACEIT, ВК и выкладка всё равно отработают, а запуск станет красным и GitHub напишет вам на почту. Если FTP падает с `550 Can't change directory`, workflow сам сбрасывает файл состояния выкладки и грузит заново.

**Секреты** (Settings → Secrets and variables → Actions):
- `FACEIT_API_KEY`: ключ FACEIT (Server side).
- `VK_TOKEN`: сервисный ключ приложения ВК (для `wall.get` достаточно его).
- `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, `FTP_DIR` (папка сайта, например `/public_html/`), при необходимости `FTP_PROTOCOL` (`ftps`).
- `MODERATOR_PASSWORD`: пароль для `moderation.html`, не короче 10 символов. На сервер попадает только его хеш (`api/config.php`). Если секрет не задан, FTP-деплой сохраняет существующий серверный конфиг; если секрет задан, конфиг генерируется перед выкладкой.

Без секрета соответствующий шаг пропускается. Проверка сервера: откройте `/api/vk.php?action=ping`, должно быть `"configured":true` и `"dataWritable":true`.

### Что не автоматизируется
- **Список ПК-клубов ВК** (`scripts/vk-clubs.mjs`): поиск групп работает только с пользовательским токеном, а он живёт сутки. Запускайте раз в месяц и коммитьте `data/clubs.json`.
- **Каталог ручных турниров**: записи добавляются в `data/static-tournaments.json`. Этот файл используется и главной страницей, и SEO-генератором.
- Ключи и пароли в репозиторий класть нельзя, только в Secrets.

### Тесты
`node --test scripts/test.mjs`: разбор дат и призов, фильтры, группировка и публикация. Запускаются автоматически перед каждой выкладкой.


## 7. Защита и новые файлы

- `data/.htaccess` закрывает прямое чтение кандидатов ВК, статистики обхода и служебных справочников на Apache-хостинге. Публичными остаются `faceit.json`, `vk.json` и `static-tournaments.json`.
- `api/.htaccess` закрывает прямой HTTP-доступ к `api/config.php` и временным файлам.
- Корневой `.htaccess` задаёт базовые защитные HTTP-заголовки. Если хостинг не использует Apache или запрещает `.htaccess`, настройте эквивалентные правила в панели хостинга.
- `api/vk.php?action=load` отдаёт кандидатов и статистику только после проверки сессии модератора. `moderation.html` больше не загружает эти файлы напрямую.
- Сохранение решений, списка скрытых клубов и опубликованного списка сериализовано файловой блокировкой `data/.vk-save.lock`; чтение набора файлов тоже использует совместную блокировку. Этот lock-файл исключён из Git и FTP-синхронизации, чтобы не прерывать активную операцию. При ошибке записи API пытается восстановить предыдущее состояние.
- GitHub Pages публикует только публичный статический набор: главную, SEO-каталог, публичные JSON и sitemap. PHP API, модерация, кандидаты, скрипты и служебные данные в артефакт Pages не попадают. Полноценная модерация работает на PHP-хостинге.

При выкладке на FTP убедитесь, что сервер поддерживает `.htaccess` и что правила `data/.htaccess` и `api/.htaccess` не удаляются FTP-клиентом.
