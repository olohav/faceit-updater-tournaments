# КиберРадар

Сайт-агрегатор турниров по CS2, Dota 2, Valorant и MLBB для России.
Статический сайт (`index.html`) + автосбор FACEIT (`scripts/`) + аккаунты, роли и ручные турниры (Supabase) + форма обратной связи (Formspree).

## Структура
| Путь | Назначение |
|---|---|
| `index.html` | весь сайт |
| `data/faceit.json` | турниры FACEIT (обновляется скриптом) |
| `data/vk.json` | одобренные вами анонсы ПК-клубов из ВКонтакте (собирается скриптом, сайт читает его) |
| `data/vk-candidates.json` | все найденные анонсы из ВК (пишет только автосбор) |
| `data/vk-decisions.json` | ваши одобрения и правки (пишет только `review.mjs`) |
| `data/organizers.json` | кэш имён организаторов (ускоряет скрипт) |
| `scripts/config.mjs` | **все настройки отбора**: игры, поисковые слова, фильтры |
| `scripts/sync-faceit.mjs` + `api/filters/format/parse/dates.mjs` | сбор и обработка данных |
| `supabase/schema.sql` | база: аккаунты, роли, турниры администратора |
| `.github/workflows/` | автообновление и публикация |

## 1. Автоматический сбор FACEIT
GitHub: Settings → Secrets → Actions → секрет `FACEIT_API_KEY` (ключ типа Server side). Workflow «Update site data» запускается каждый час (подробнее в разделе 6).
Локально: `set FACEIT_API_KEY=ключ` и `node scripts\sync-faceit.mjs`. С `set FACEIT_DEBUG=1` скрипт дополнительно создаёт `data/filter-report.json`: сколько турниров отсеяно по каждой причине и примеры названий. Так видно, не выпадает ли нужное.

## 2. Обратная связь на почту (Formspree, бесплатно)
1. formspree.io → зарегистрироваться (почта dezhenkov62@gmail.com) → New form.
2. Скопировать адрес формы вида `https://formspree.io/f/xxxxxxx`.
3. В `index.html` вписать его в `const FEEDBACK_ENDPOINT = "…"`. Письма будут приходить на почту, на которую зарегистрирована форма. Лимит бесплатного тарифа — несколько десятков сообщений в месяц.

## 3. Аккаунты, роли и админ-панель (Supabase, бесплатно)
1. supabase.com → New project (регион поближе, придумайте пароль БД).
2. SQL Editor → New query → вставить `supabase/schema.sql` → Run.
3. Project Settings → API: скопировать **Project URL** и ключ **anon public**. В `index.html` вписать в `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Ключ `service_role` в сайт вставлять нельзя.
4. Authentication → URL Configuration: в Site URL указать адрес сайта (например `https://olohav.github.io/faceit-updater-tournaments/`).
5. Зарегистрироваться на сайте почтой администратора, подтвердить письмо, затем в SQL Editor выполнить:
   `update public.profiles set role = 'admin' where email = 'dezhenkov62@gmail.com';`
6. Выйти и войти заново: в шапке появится «Администратор» и «Админ-панель».

Безопасность: права проверяет сама база (политики RLS), а не страница. Обычный пользователь не может ни добавить турнир, ни изменить свою роль, даже если подправит код в браузере.

## Роли
- **Пользователь**: регистрация и вход, форма обратной связи с подставленной почтой.
- **Администратор**: всё то же + вкладка «Админ-панель»: добавление, редактирование, удаление турниров, дата автоудаления.

## 4. Страницы для поисковиков (SEO)
Главная страница рисуется скриптом и использует адреса вида `#/t/…`, которые поисковики не индексируют отдельно. Поэтому `scripts/build-pages.mjs` создаёт обычные HTML-страницы:
- `t/<id>/index.html` — страница каждого актуального турнира (заголовок, описание, разметка schema.org для поиска, ссылки на похожие турниры);
- `t/index.html` — каталог всех турниров;
- `sitemap.xml` и `robots.txt` — для Яндекса и Google.

Источники: `data/faceit.json`, ручные записи из `index.html` и турниры администратора из Supabase (берутся автоматически, если подключён).
Адрес сайта указан в `site.config.json` (`siteUrl`). **При смене домена поправьте его там и запустите скрипт заново.**

Запуск на Windows: `update-site.bat` (обновляет данные FACEIT и создаёт страницы). Затем загрузите на хостинг в корневую папку сайта: `data/faceit.json`, папку `t/`, `sitemap.xml`, `robots.txt` (и `index.html`, если он менялся). Завершённые турниры при каждом запуске исчезают из `t/`, поэтому папку `t/` на хостинге лучше заменять целиком.

После публикации на своём домене: добавьте сайт в Яндекс Вебмастер (webmaster.yandex.ru) и Google Search Console, укажите адрес `…/sitemap.xml`.

## 5. ВКонтакте: от поста клуба до сайта
1. **Автосбор** (GitHub, раз в 6 часов): `scripts/vk-tournaments.mjs` читает стены клубов из `data/clubs.json`, находит анонсы и кладёт их в `data/vk-candidates.json` со статусом «на проверке». На сайт они **не попадают**.
2. **Ваша проверка** (на компьютере): запустите `review.bat`, он скачает свежих кандидатов и откроет `http://localhost:3000`. Одобряйте, отклоняйте, правьте название, дату, приз. Решения пишутся в `data/vk-decisions.json`.
3. **Отправка**: закройте проверку (Ctrl+C, затем Y) и запустите `publish-review.bat`. Он отправит ваши решения на GitHub.
4. **Публикация** (GitHub, автоматически): workflow `Update site data` увидит новый `vk-decisions.json`, соберёт `data/vk.json` (только одобренные и ещё не начавшиеся), обновит страницы для поисковиков и выложит всё на хостинг. Через 1-3 минуты турниры на сайте.

Одобренные турниры уходят с сайта сами, когда наступает время старта. Чтобы автосбор и ваши решения никогда не конфликтовали в git, каждый файл пишет только один «владелец» (см. таблицу выше).

## 6. Полная автоматизация на GitHub
Один workflow `Update site data` (`.github/workflows/update-data.yml`):

| Когда | Что делает |
|---|---|
| каждый час | FACEIT, пересборка `vk.json`, страницы, коммит, FTP |
| каждые 6 часов | то же + обход ВК-групп клубов (около 30 минут) |
| вы сделали push решений | пересборка `vk.json`, страницы, коммит, FTP |
| кнопка Run workflow | всё сразу |

Источники не зависят друг от друга: если упал FACEIT, ВК всё равно соберётся и выложится, а запуск станет красным, и GitHub напишет вам на почту.

**Секреты** (Settings → Secrets and variables → Actions):
- `FACEIT_API_KEY`: ключ FACEIT (Server side). Без него шаг FACEIT пропускается.
- `VK_TOKEN`: сервисный ключ приложения ВК (для `wall.get` достаточно его). Без него обход ВК пропускается, но `vk.json` всё равно пересобирается из ваших решений.
- `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`: данные FTP из панели хостинга. Необязательные: `FTP_DIR` (папка сайта на сервере, по умолчанию `/`) и `FTP_PROTOCOL` (`ftp` по умолчанию, можно `ftps`). Пока `FTP_SERVER` не задан, загрузка на хостинг пропускается.

Опубликовать сайт можно двумя способами одновременно: хостинг по FTP (выше) и GitHub Pages (Settings → Pages → Source: GitHub Actions; `static.yml` запускается после каждого обновления данных).

### Что не автоматизируется
- **Список ПК-клубов ВК** (`scripts/vk-clubs.mjs`): поиск групп работает только с пользовательским токеном, а он живёт сутки. Список собирается вручную раз в месяц или реже, затем `data/clubs.json` коммитится в репозиторий.
- **Поиск по открытому интернету**: турниры из `TOURNAMENTS` в `index.html` добавляются вручную.
- Ключи ВК, FACEIT и FTP в репозиторий класть нельзя, только в Secrets.
